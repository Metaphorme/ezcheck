# 算法后端采用可叠加能力特性

Cargo 特性会在依赖图中做并集，互斥后端会使下游启用组合特性时编译失败。因此 `hashes_backend` 与 `ring_backend` 被定义为可叠加的能力特性，`mix_backend` 仅作为同时启用两者的兼容别名；两者同时提供 SHA 实现时固定优先使用 ring，以保持结果确定并避免重复计算。

## Consequences

- `--all-features` 和依赖方的特性合并始终可编译
- 可选依赖通过 `dep:` 保持为实现细节，不泄露同名隐式特性
- 新后端必须与已有能力叠加，而不能通过 `compile_error!` 声明互斥
- 后端优先级属于实现决策，不改变公开的哈希算法名称或摘要格式
